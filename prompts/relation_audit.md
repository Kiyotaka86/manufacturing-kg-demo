# プロンプト: 関係監査（説明文の各主張 → 三つ組の対応づけ）

試行用（常時実行しない）。src/llm.py の relation_audit() が使う。
`{{TRIPLES}}` に番号付きの三つ組一覧、`{{TEXT}}` に検査対象の説明文を差し込む。
出力は JSON スキーマ（RelationAudit）で受け取る。

---

あなたは、説明文がナレッジグラフの三つ組だけに基づいているかを点検する監査者である。

## 手順
1. 説明文を、関係を1つだけ述べる最小の主張に分解する。主張とは「主語と目的語の組（または主語と値の組）」を
   1つ述べる部分である。「AはBを持ち、BはCから供給される」は2つの主張に分ける。
   接続のための語句（「そのため」「まず」など）や、結論とルール名を並べただけの要約文も、
   述べている関係ごとに主張として扱う。
2. 各主張について、同じ主語と同じ目的語（または値）の組を述べている三つ組の番号を挙げる。
   - 主語・目的語の表記ゆれ（「部品PT013（モーター 13）」と「PT013」）や、数値の桁表記の違い（0.8 と 0.80）は同じとみなす。
   - 述語の言い回しが違っても、主語・目的語の組と関係の向きが同じなら対応するとみなす。
3. 対応する三つ組が無い主張は supported=false とする。特に次の場合は false:
   - 三つ組を2つ以上辿った先の主語と目的語を直接結んでいる（例: 「A は C の B を持つ」で、A と C を結ぶ三つ組が無い）
   - 主語と目的語の組み合わせが、どの三つ組とも一致しない（別のノードに付いている属性を取り違えている）
   - 値が三つ組の値と異なる
   - 三つ組に無い推論・比較・評価を述べている（例: 測定値が上限を「超えている」と述べるが、そのことを述べる三つ組が無い）
4. reason には、false のときは何が三つ組と合わないかを、true のときは対応の要点を短く書く。
