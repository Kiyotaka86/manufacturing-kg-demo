オントロジーとコンピテンシークエスチョンの読み方

製造・品質トレーサビリティの予行練習デモで、オントロジーが何を表し、各 CQ がそのどこを辿り、何が分かるのかを一枚にまとめたもの。

評価の低いサプライヤー S005（ミナト金属）の部品が使われている。どこに使われ、誰に届き、何が起き、どう判断し、どうすべきか。

デモの CQ はすべて、この一つの問いに順番に答えている。

CQ の4つの種類

CQ は答え方で4種類に分かれる。本番の価値仮説「なぜその結論に至ったかを説明できる」に直接対応するのは「判断する」と「基準を問う」。「辿る」「数える」は、その判断の材料をグラフから取り出せることを示す前段にあたる。

種類CQ答えの形分かること
辿る01〜03結果テーブル事実がどう繋がっているか
数える04〜05集計テーブルどこに問題が集中しているか
判断する06〜08（09 は未実装）経路グラフ＋説明文なぜその結論か
基準を問う10（タブ2）判定の差分一覧その結論は基準次第でどう変わるか

オントロジー概念図と CQ の経路

CQ を選ぶと、その CQ が辿るクラスと関係が図上で強調される。クラスをクリックすると、属性と接続する関係を表示する。

マスタ 関係・実績レコード 判定根拠 判断ルール オブジェクトプロパティ 導出プロパティ（チェーン）

各 CQ の問い・見えるもの・分かること

問いと実装の食い違い

各 CQ のクエリ（queries/cq*.rq）を読み合わせた結果、冒頭コメントの問いと実装が一致していない箇所がある。説明は実装に合わせて記載しているが、デモで問いを読み上げる場合は以下に注意する。

CQ問い実装デモでの扱い
CQ02ロット・工程・部品・サプライヤーに遡る出力はクレーム・ロット・設備・供給元のみ「設備と供給元まで遡る」と説明する
CQ03出荷済みの顧客ship_date を条件にしておらず、未出荷の受注も拾いうる。全60件中3件が未出荷S005 では未出荷の3件は該当せず、結果はすべて出荷済み。そのまま見せてよい
CQ04直近3ロットの不良率全ロットで集計。分子はクレーム件数のため不良率が 1 を超える行がある（S001×PT024 で 2.0）。比較は >= 固定で、ルールの比較方向・最小標本数を使っていない判定ではなく傾向の表として見せる。判定は CQ06 に任せる
CQ05平均日数SPARQL は保全ごとの次の不良日を返し、平均はそのテーブルから外で計算している問いには答えている。ただし「計算は SPARQL で完結させる」方針の例外になる
CQ08サプライヤーの代替候補対象は部品。既定値 PT013 は候補0件PT014 を選んで見せる
CQ10閾値変更で判定が変わるロット単体クエリは比較 >= 固定でアプリ未使用。既定 0.10 では全サプライヤーが閾値を大きく上回り0件。タブ2が役割を担うタブ2で見せる

これは「ルールの記述と実装を照合する工程を設ける」という持ち帰り事項が、ルールだけでなく CQ にも当てはまることを示している。

本番（トレーディング）との対応

4つの種類は、ドメインが変わっても同じ型で使える。

種類製造デモトレーディングでの例
辿る部品 → ロット → 顧客顧客 → 過去取引 → 銘柄・相場条件
数えるサプライヤー別の不良率顧客別の成約率、条件別のスプレッド
判断するロットは要注意か、なぜかこのオファー水準は妥当か、なぜか
基準を問う閾値を変えたら判定はどう変わるか強気度の基準を変えたら推奨はどう変わるか

名前空間は仮（ex: = http://example.org/kg/ontology#）。スキーマは urn:schema:kg、事実データとルールはシートごとに urn:src:<シート名>（16グラフ）、導出プロパティは urn:derived:chains、判定結果は urn:src:evidence（what-if は urn:whatif:evidence）に格納。CQ の経路は各クエリが使うプロパティから描いている。クラス・属性・CQ の経路・数値は、リポジトリの ontology/schema.ttl・queries/*.rq と Fuseki 上のデータに照合済み（2026-10-04、合成データ data/kg_toolkit.xlsx）。CQ09 はアプリでは未実装。
