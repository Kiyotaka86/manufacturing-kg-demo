# デモ手順書

製造・品質トレーサビリティのナレッジグラフ デモを、事前準備から進行まで再現するための手順。
期待される結果の値は、2026-10-04 に下記の手順を実行して得た実測値（合成データ `data/kg_toolkit.xlsx`）。

- 所要時間の目安：事前準備 5 分（初回のセットアップを除く）、デモ本編 20〜25 分
- 前提：[README.md](../README.md) のセットアップが済んでいること（Homebrew の `jena` `fuseki` `uv`、`uv sync`、`.env`）

## 1. 事前準備

コマンドはすべて**リポジトリ直下**で実行する（`config/fuseki.ttl` のデータ位置 `run/databases/kg` が相対パスのため）。

### 1-1. Fuseki を起動（ターミナル A。起動したままにする）

```bash
fuseki-server --config=config/fuseki.ttl
```

別のターミナルで接続を確認する。

```bash
uv run scripts/check_fuseki.py
# → PUT graph <urn:src:test>: 201 / triple count: 3 / DELETE graph <urn:src:test>: 204 / OK
```

### 1-2. データ投入（ターミナル B）

通常は次の1コマンドでよい。変換 → SHACL 検証 → 投入 → 導出プロパティの実体化 → 判定、までを順に実行する。

```bash
uv run src/load.py
```

期待される出力（抜粋）:


<summary>各ステップを個別に実行する場合</summary>

```bash
# (1) xlsx → TriG 変換 + SHACL 検証（違反があれば exit 1 で止まる）
uv run scripts/xlsx_to_rdf.py data/kg_toolkit.xlsx ontology/schema.ttl ontology/shapes.ttl data/kg.trig

# (2) SHACL 検証だけを再実行

# (3) Fuseki への投入は load.py が担う（スキーマ → 16 グラフ → 実体化 → 判定）
uv run src/load.py

# (4) 導出プロパティ（lotUsesSupplier / lotMadeOn / partSuppliedBy）の実体化だけをやり直す
for f in queries/materialize_*.rq; do
  curl -s -o /dev/null -w "$f %{http_code}\n" http://localhost:3030/kg/update --data-urlencode "update@$f"

# (5) 判定（urn:src:evidence）だけをやり直す
uv run src/evidence.py

# (6) Fuseki 上の全グラフ（Evidence を含む）を SHACL 検証
uv run src/validate.py --fuseki
```

</details>

### 1-3. Streamlit を起動（ターミナル B）

```bash
uv run streamlit run src/app.py
```

http://localhost:8501 を開く。サイドバーに「● 接続中」「19 graphs / 6,968 triples」と出ていれば準備完了。

### 1-4. 解説ページを開く

`docs/ontology_and_cq.html` はオフラインでも動く単一 HTML（外部依存は Google Fonts のみ。オフライン時はシステムフォントで表示される）。

```bash
# 直接開く
open docs/ontology_and_cq.html

# または HTTP で配信する（別ターミナル）
uv run python -m http.server 8000 --directory docs
# → http://localhost:8000/ontology_and_cq.html
```

CQ のチップを押すと、その CQ が辿るクラスと関係が概念図上で強調される。クラスを押すと、属性・関係・そのクラスを通る CQ が右のパネルに出る。

## 2. デモの進行

### 筋書き

> 評価の低いサプライヤー **S005（ミナト金属、評価 2）** の部品が使われている。
> どこに使われ、誰に届き、何が起き、どう判断し、どうすべきか。

CQ はこの一つの問いに順番に答える。種類ごとに「**辿る（01〜03）→ 数える（04〜05）→ 判断する（06〜08）→ 基準を問う（10）**」の順で進める。

各 CQ の冒頭で解説ページのチップを押して経路を見せてから、アプリで実行するとよい。

アプリの操作は共通で、タブ1「質問する」の「CQ を選ぶ」で CQ を選び、「対象を選ぶ」で対象を選んで「実行」を押す。対象は、特記がなければ既定値のままでよい。

### 2-1. 辿る（CQ01〜03）— 事実がどう繋がっているか

### 2-4. 基準を問う（CQ10）— その結論は基準次第でどう変わるか

CQ10 は単体のクエリ（`queries/cq10.rq`）としても残っているが、アプリでは**タブ2「閾値を変える」**が役割を担う。

| CQ | 画面上の操作 | 期待される結果 | 説明のポイント |
| --- | --- | --- | --- |
| CQ10 閾値を変えたら | タブ2 を開き、「R01 閾値（不良率）」を 0.05 → **0.30** にして「再判定」を押す | 判定ありロット **64 → 41（−23）**。変更前のみ 23 ロット、両方 41 ロット、変更後のみ 0 ロット。「両方」のうち 10 ロットで該当ルールが変わる（例：**`L0048  R02+R03 ← R01+R02+R03`**） | 結論は、閾値という人間が決めた基準に依存する。経路で説明できるからこそ、基準の妥当性を議論の俎上に載せられる。`rules` グラフは書き換えず、what-if の結果は `urn:whatif:evidence` に書く |
| （続き） | 「両方」列の `L0048` を押す → タブ1 の CQ06 が what-if の判定で開く | **判定: 出荷保留**。R03 と R02（33 日、閾値 30 日）のみが残り、R01（S002 北陸ベアリング 2 / 11 = 0.18）が外れる。経路グラフは確定判定の 15 ノード・24 エッジから **10 ノード・15 エッジ**に縮む | 基準を変えると、結論だけでなく根拠経路そのものが変わる。「参照する判定」のラジオで確定と what-if を切り替えて比べられる |

デモ後は、サイドバーの「判定を再生成」を押すか `uv run src/load.py` を再実行すると、what-if の結果が消えて初期状態に戻る。

## 3. 想定される失敗と対処

| 症状 | 原因 | 対処 |
| --- | --- | --- |
| サイドバーが未接続、タブ1 に「Fuseki に接続できません」 | Fuseki 未起動、または `FUSEKI_URL` の誤り | ターミナル A で `fuseki-server --config=config/fuseki.ttl` を起動する（リポジトリ直下で）。`uv run scripts/check_fuseki.py` で確認する。`.env` の `FUSEKI_URL` が `http://localhost:3030/kg` か確認する |
| `load.py` が `httpx.ConnectError` で止まる | 同上 | 同上 |
| Fuseki 起動時に `Address already in use`（3030） | 別の Fuseki などがポートを使用中 | `lsof -iTCP:3030 -sTCP:LISTEN` で使用プロセスを確認する。既存の Fuseki がこのリポジトリのものならそのまま使ってよい。別ポートで起動する場合は `fuseki-server --port 3031 --config=config/fuseki.ttl` とし、`.env` の `FUSEKI_URL` を `http://localhost:3031/kg` に変える |
| Streamlit が 8501 で起動しない | ポート競合 | `lsof -iTCP:8501 -sTCP:LISTEN` で確認する。`uv run streamlit run src/app.py --server.port 8502` で別ポートにする |
| 説明文が出ない、自由入力が使えない（「ANTHROPIC_API_KEY が未設定のため…」） | API キー未設定 | `.env` に `ANTHROPIC_API_KEY=` を記入して Streamlit を再起動する。キーがなくても判定・経路グラフ・閾値変更は動くので、デモはそのまま続けられる |
| 説明文の生成でエラー | API キーが無効、またはネットワーク不通 | サイドバーの「説明文を生成」をオフにして続ける |
| `load.py` が `SHACL conforms: False` の後、違反レポートを出して止まる | xlsx の値が `ontology/shapes.ttl` の制約に違反している（必須値の欠落、型・参照先の誤りなど） | 投入は行われず、Fuseki は前回の状態のまま。レポートの `Focus Node`・`Result Path`・`Message` で該当シートの行と列を特定し、`data/kg_toolkit.xlsx` を直してから再実行する |
| CQ の結果が手順書と違う | 前回の what-if が残っている、または判定が古い | サイドバーの「判定を再生成」を押すか、`uv run src/load.py` を再実行する |
| Fuseki が `TDB2` のロックエラーで起動しない | 別の Fuseki プロセスが同じ `run/databases/kg` を開いている | 既存プロセスを止めてから起動する（`lsof -iTCP:3030 -sTCP:LISTEN` で PID を確認する） |
